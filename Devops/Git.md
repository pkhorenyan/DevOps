Как удалить локальную ветку

Вы не можете удалить ветку, на которой сейчас находитесь. Сначала переключитесь на другую (например, `main`). 

- **Безопасное удаление:**  
    `git branch -d <название_ветки>`  
    _Git не даст удалить ветку, если в ней есть неслитые изменения._
- **Принудительное удаление:**  
    `git branch -D <название_ветки>`  
    _Используйте, если хотите удалить ветку вместе со всеми незавершенными изменениями._

Как удалить ветку в GitLab (удаленно)

Если вам нужно удалить ветку не только у себя, но и на сервере:

 ```shell
 git push origin --delete <название_ветки>
 ```

## Merge

Перейдите в ветку, **в которую** вы хотите влить изменения (обычно это `main`), и выполните команду `merge`:

```bash
# Переходим в целевую ветку
git checkout main

# Вливаем изменения из ветки feature в текущую (main)
git merge feature
```

Если во время слияния что-то пошло совсем не так, можно всё откатить командой:

```bash
git merge --abort
```
## Rebase

Rebase из ветки master в нашу нынешнюю - подтягиваем коммиты

```shell
git rebase master
```

## Интерактивный rebase

Укажите, на сколько коммитов назад вы хотите вернуться. Например, для последних 3-х:  
```shell
git rebase -i HEAD~3
```
Или укажите хеш коммита, **стоящего перед** теми, что нужно объединить:

```shell
git rebase -i <hash_коммита>  
```

**Выберите коммиты для объединения**:  
Откроется текстовый редактор со списком коммитов. Они идут в хронологическом порядке (старые сверху).

- Оставьте первый (самый верхний) как `pick`.
- У всех остальных, которые нужно «влить» в первый, замените слово `pick` на `squash` (или просто `s`).

```
pick f7f3f2a Первый хороший коммит
squash 2dc518d Мелкие правки 1
squash 6940e75 Мелкие правки 2
```




# Разрешение конфликтов в Git

#### 1. Обновите локальные данные

Загрузите актуальное состояние всех веток из удалённого репозитория:

```bash
git fetch origin
```

#### 2. Переключитесь на свою ветку

```bash
git checkout your-feature-branch
```

#### 3. Влейте изменения из целевой ветки

Конфликты решаются через `merge` или `rebase`. Выберите подходящий способ:

**Способ 1: Merge** — создаёт новый коммит слияния, проще для понимания:

```bash
git merge origin/main
```

**Способ 2: Rebase** — переносит ваши коммиты поверх новых изменений `main`, история остаётся линейной и чистой:

```bash
git rebase origin/main
```

#### 4. Разрешите конфликты

Git остановится и подсветит проблемные файлы. Откройте их в редакторе, найдите маркеры конфликтов, удалите их и оставьте правильный итоговый код. Сохраните файлы.

```
<<<<<<< HEAD
// ваши изменения
=======
// изменения из main
>>>>>>> origin/main
```

#### 5. Завершите процесс

Подготовьте разрешённые файлы и зафиксируйте результат.

**Если вы делали merge:**

```bash
git add .
git commit -m "Fix merge conflicts"
```

**Если вы делали rebase:**

```bash
git add .
git rebase --continue
```

#### 6. Отправьте изменения обратно

Если вы использовали `rebase`, обычный пуш не сработает, так как история изменилась. Потребуется принудительная отправка с флагом `--force`:

```bash
git push origin your-feature-branch --force
```

После этого Merge Request в интерфейсе (GitLab/GitHub) обновится автоматически и покажет, что конфликтов больше нет.
